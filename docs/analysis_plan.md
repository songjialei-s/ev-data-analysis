# 真实充电订单后续分析框架

## 1. 范围与原则

本文件规划后续分析问题，不执行 SQL、不制作 Power BI，也不批量生成结果。分析将只使用真实数据清洗形成的私有事实表和 `docs/metric_definition.md` 中已经定义的口径，不使用旧合成数据或旧结论。

所有停止原因归因、收入确认、支付滞后和时间归属等待确认事项，必须在正式分析前得到业务确认。下文“可能输出的业务结论”只描述结论类型，不代表已经从数据中得到这些结论。

## 2. 运营总览

**要回答的业务问题**

- 数据期间内订单、用户、活跃枪口、充电量和应付/实付规模是多少？
- 订单规模与实际交付电量是否同步变化？
- 零电量启动和未支付是否对整体表现形成明显影响？

**使用指标**

订单量、充电量、总应付金额、总实付金额、平均订单金额、平均充电量、平均充电时长、活跃用户数、活跃充电枪数、零电量启动率、未支付率。

**使用维度**

日期（日/周/月）、站点、订单类型、启动方式、支付状态。时间默认按 `chargeBegin` 归属。

**适合图表**

KPI 卡片、订单量与充电量双轴趋势图、应付与实付对比图、状态构成条形图。展示时必须显式标注金额口径。

**可能输出的业务结论**

识别规模增长或回落时段、订单与电量背离、应付与实付差距扩大以及启动成功质量变化。只能描述数据现象，原因需要结合活动、价格、设备和客流信息验证。

## 3. 站点分析

**要回答的业务问题**

- 哪些站点贡献主要订单、充电量和应付/实付金额？
- 在“期间活跃枪口”口径下，各站点的单枪订单、充电量和收入有何差异？
- 哪些站点零电量启动、未支付或异常停止相对集中？

**使用指标**

订单量、充电量、总应付金额、总实付金额、活跃充电枪数、单枪订单量、单枪充电量、单枪收入、每 kWh 收入、未支付率、零电量启动率、异常停止率（待字典确认）。

**使用维度**

`stationName`、`stationName + plugNum`、日期、启动方式、停止原因分类（待确认）。

**适合图表**

站点排名条形图、订单—充电量散点图、单枪效率点图、站点×异常类型热力图、站点趋势小 multiples。站点名称是否允许公开需业务确认。

**可能输出的业务结论**

识别规模贡献集中度、活跃枪口产出差异、订单多但单均电量偏低的站点，以及异常/未支付相对集中的站点。不得将活跃枪数解释为配置枪数，也不得据此直接声称设备利用率高低。

## 4. 时间与峰谷分析

**要回答的业务问题**

- 订单、充电量和金额在一天、一周及月份内如何分布？
- 工作日与周末是否存在不同的充电节奏？
- 峰、平、谷、尖峰等分项电量和费用结构如何变化？
- 零电量启动或异常停止是否集中在特定时段？

**使用指标**

订单量、充电量、总应付金额、电费、服务费、平均充电量、平均充电时长、零电量启动率、异常停止率，以及各峰谷分项的电量和费用。

**使用维度**

日期、月份、星期、工作日/周末、开始小时、站点、峰谷时段字段。法定节假日口径当前没有数据支持，待补充日历后再分析。

**适合图表**

日/周趋势折线图、小时×星期热力图、工作日与周末分组柱形图、峰谷结构堆叠图、小时异常率折线图。

**可能输出的业务结论**

描述需求高峰、低谷窗口、周内规律、峰谷电量结构及异常集中时间，为排班、巡检或价格策略提出待验证假设；不能仅凭订单时间推断排队或容量不足。

## 5. 收益结构分析

**要回答的业务问题**

- 应付、实付、电费、服务费和优惠分别是多少，彼此差异来自哪里？
- 哪些站点、时段或用户群贡献主要应付与实付金额？
- 每 kWh 应付金额和服务费占比是否存在明显结构差异？
- 未支付和优惠对实付形成多大影响？

**使用指标**

总应付金额、总实付金额、电费、服务费、优惠金额、平均订单金额、每 kWh 收入、服务费占比、未支付率、费用不守恒率、实付守恒异常率。

**使用维度**

日期、站点、枪口、峰谷时段、支付状态、支付方式、订单类型、启动方式、脱敏用户分层（分层规则需另行确认）。

**适合图表**

应付到实付瀑布图、收入构成堆叠柱形图、站点每 kWh 收入箱线图、服务费占比点图、未支付金额趋势图。

**可能输出的业务结论**

说明应付与实付差距、服务费结构、优惠和未支付的集中位置，以及不同站点/时段的单位电量金额差异。不得把应付金额称为到账收入，也不得把服务费占比解释为毛利率。

## 6. 用户行为分析

**要回答的业务问题**

- 脱敏用户的活跃规模、复购频次、充电量和消费分布如何？
- 高频与低频用户在站点、时间、充电量和支付行为上是否不同？
- 用户贡献是否高度集中，用户跨站使用是否普遍？

**使用指标**

活跃用户数、用户订单量、用户充电量、用户应付/实付金额、平均订单金额、平均充电量、平均充电时长、未支付率、零电量启动率。

**使用维度**

仅使用脱敏 `user_id`（当前实现 `user_key`）、日期、站点、开始小时、工作日/周末、订单类型、支付状态。不得回连或输出原始用户号、车牌、VIN。

**适合图表**

用户频次分布直方图、用户贡献 Pareto 图、留存/复购队列热力图、用户×站点迁移矩阵、用户群指标对比图。任何用户级展示必须设置最小群组阈值，阈值待隐私规范确认。

**可能输出的业务结论**

描述用户活跃与贡献集中度、复购节奏、跨站行为和不同匿名群体的充电特征。不得尝试识别个人，也不得在样本过小时披露可关联行为轨迹。

## 7. 停止原因与异常分析

**要回答的业务问题**

- 停止原因如何分布，哪些属于正常完成、用户、车辆、设备、平台或通信原因？
- 零电量启动与哪些停止原因、站点、枪口和时间段关联？
- 异常是否集中于少数站点/枪口，是否具有持续性或突发性？
- 数据质量异常与真实运营异常能否明确区分？

**使用指标**

异常停止率、零电量启动率、设备类异常占比、订单量、充电量、平均充电时长、SOC 数据异常率、费用不守恒率。

**使用维度**

`endReason` 原始值、经审批的原因大类、站点、枪口、日期、小时、启动方式、订单类型、SOC 状态、是否零电量。

**适合图表**

停止原因 Pareto 图、原因大类堆叠图、站点×原因热力图、异常日历热力图、枪口异常趋势控制图、零电量与原因交叉矩阵。

**可能输出的业务结论**

识别高频停止原因、设备/通信类异常的集中位置、重复发生的枪口和可能需要优先排查的时段。正式结论前必须由业务与设备团队确认原因映射；文本关键词归类只能作为探索性假设。

## 8. 进入下一阶段前的确认清单

1. 审批 `endReason` 的正常/用户/车辆/设备/平台/通信分类字典。
2. 确认应付、实付、退款、冲正、部分支付和跨期支付的财务口径。
3. 确认 `chargingPower` 的单位，以及峰谷分项字段的时段含义。
4. 确认订单按开始时间还是结束时间归属分析期间。
5. 确认站点名称和聚合结果的对外公开权限。
6. 确认用户分群及最小群组展示阈值，避免重新识别风险。

上述事项确认后，再决定是否进入 SQL 实现；本阶段不进入 Power BI。
