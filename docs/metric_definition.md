# 真实充电订单指标口径

## 1. 适用范围与统一约定

本文只定义指标，不输出大规模分析结果，也不涉及 SQL 或 Power BI。所有指标均基于真实订单清洗形成的私有事实表，不使用仓库旧合成数据或旧版业务结论。

统一数据基础如下：

- **可信订单事实表**：通过主键和云平台时间检查的清洗结果。一行代表一笔订单；零电量、未支付、异常停止等具有分析价值的记录仍保留并打标。
- **有效充电订单**：可信订单事实表中 `chargingPower > 0` 的记录。仅在指标明确要求实际交付电量时使用，不能替代全部订单口径。
- **时间字段**：默认使用云平台 `chargeBegin` 归属日期、小时和数据期间；跨期订单是否按开始时间归属，标记为待确认。
- **用户字段**：文档中的脱敏 `user_id` 指清洗表里的盐化标识 `user_key`。不得使用原始 `userNum`，字段名称是否统一改为 `user_id` 待后续实现时确认。
- **枪口标识**：只能使用 `stationName + plugNum` 复合去重。`plugNum` 可能在不同站点重复，不能单独作为全局枪口主键。
- **异常停止**：必须基于经业务确认的 `endReason` 分类字典。当前尚无正式字典，涉及异常停止分类的指标均为“待确认”，不能凭文本自行定性。
- **金额单位**：沿用源数据币种，当前文档不擅自假设为人民币；展示单位待业务确认。
- **空值处理**：金额、电量或用户标识缺失时不得默认填 0。分子求和、分母计数和缺失率应同时披露。

“是否包含”列中的“是”表示该类记录只要仍在可信事实表中就参与计算；“否”表示该指标有明确排除条件；“条件包含”表示只有满足该指标特定字段条件时才参与。

## 2. 运营规模

| 指标名称 | 业务含义 | 使用字段 | 计算公式 | 数据过滤条件 | 包含未支付订单 | 包含异常停止订单 | 包含零电量订单 | 粒度 | 注意事项 / 待业务确认点 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 订单量 | 数据期间内形成的可信充电订单数量，反映订单/启动规模 | `orderNum` | `COUNT(DISTINCT orderNum)` | 可信订单事实表；`orderNum` 非空且唯一 | 是 | 是 | 是 | 全局、日/周/月、站点、枪口、用户 | 它不是“成功充电次数”。是否另设成功充电订单量，待业务确认 |
| 充电量 | 实际交付的总电量 | `chargingPower` | `SUM(chargingPower)` | `chargingPower >= 0`；缺失单独报告 | 是 | 是 | 是，数值为 0 | 全局、时间、站点、枪口、用户、峰谷 | 源字段名为 Power，但业务含义按 kWh 电量使用；单位需与业务方确认 |
| 活跃用户数 | 数据期间至少出现一笔可信订单的脱敏用户数 | 脱敏 `user_id`（当前实现为 `user_key`） | `COUNT(DISTINCT user_id)` | `user_id` 非空；仅使用脱敏字段 | 是 | 是 | 是 | 全局、日/周/月、站点 | 内部订单缺少用户标识时不进入人数分母，但订单仍保留；跨盐版本不可直接去重 |
| 活跃充电枪数 | 数据期间真实订单中出现过的站点—枪口组合数 | `stationName`, `plugNum` | `COUNT(DISTINCT (stationName, plugNum))` | 两字段均非空；可信订单事实表 | 是 | 是 | 是 | 全局、时间、站点 | 只能解释为“期间内出现过的活跃枪数”，绝不能解释为站点真实配置枪数或可用枪数 |

## 3. 运营效率

| 指标名称 | 业务含义 | 使用字段 | 计算公式 | 数据过滤条件 | 包含未支付订单 | 包含异常停止订单 | 包含零电量订单 | 粒度 | 注意事项 / 待业务确认点 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 平均充电量 | 每笔可信订单平均交付电量 | `chargingPower`, `orderNum` | `SUM(chargingPower) / COUNT(DISTINCT orderNum)` | `chargingPower` 非空；分母为对应记录数 | 是 | 是 | 是 | 全局、时间、站点、枪口、用户 | 包含零电量可反映全部启动质量；如展示“成功订单平均充电量”，必须另标 `chargingPower > 0` |
| 平均充电时长 | 每笔可信订单平均充电时长 | `duration_minutes_calculated`；校验字段 `chargeTimeMinute` | `AVG(duration_minutes_calculated)` | 时长大于 0；以云平台起止时间计算 | 是 | 是 | 是 | 全局、时间、站点、枪口、用户 | 当前时长包含有时长但零电量的尝试。是否定义“有效充电时长”需业务确认 |
| 单枪订单量 | 每个期间活跃枪口平均承载的订单数 | `orderNum`, `stationName`, `plugNum` | `订单量 / 活跃充电枪数` | 与订单量、活跃枪数口径一致 | 是 | 是 | 是 | 全局、时间、站点 | 不是按配置枪数计算；不同时间窗口不可在未统一期间长度时直接比较 |
| 单枪充电量 | 每个期间活跃枪口平均交付电量 | `chargingPower`, `stationName`, `plugNum` | `充电量 / 活跃充电枪数` | 与充电量、活跃枪数口径一致 | 是 | 是 | 是，数值为 0 | 全局、时间、站点 | 反映活跃枪产出，不代表设备额定能力或利用率 |
| 单枪收入（应付） | 每个期间活跃枪口平均产生的应付金额 | `chargingPay`, `stationName`, `plugNum` | `SUM(chargingPay) / 活跃充电枪数` | `chargingPay` 非空；可信订单事实表 | 是 | 是 | 是 | 全局、时间、站点 | 这是应付口径，不是到账收入；如改用实付必须在名称中明确 |

## 4. 收益表现

| 指标名称 | 业务含义 | 使用字段 | 计算公式 | 数据过滤条件 | 包含未支付订单 | 包含异常停止订单 | 包含零电量订单 | 粒度 | 注意事项 / 待业务确认点 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 总应付金额 | 按订单计费规则形成、用户应付的总金额 | `chargingPay` | `SUM(chargingPay)` | `chargingPay` 非空；可信订单事实表 | 是 | 是 | 是 | 全局、时间、站点、枪口、用户 | 不能称为实收或到账收入；退款、冲正是否已反映待确认 |
| 总实付金额 | 已支付订单实际支付金额 | `chargingPayActual`, `payStatus` | `SUM(chargingPayActual)` | `payStatus = 已支付` 且实付非空 | 否 | 是 | 是 | 全局、时间、站点、枪口、用户、支付方式 | 未支付不以 0 代替；支付后退款、支付时间跨期和 16 条源实付缺失如何处理待确认 |
| 电费 | 订单应付金额中的电量电费部分 | `chargingelectricityPay` | `SUM(chargingelectricityPay)` | 字段非空；可信订单事实表 | 是 | 是 | 是 | 全局、时间、站点、枪口、峰谷 | 属于应付构成，不等同于电力采购成本或毛利 |
| 服务费 | 订单应付金额中的服务费部分 | `chargingServicePay` | `SUM(chargingServicePay)` | 字段非空；可信订单事实表 | 是 | 是 | 是 | 全局、时间、站点、枪口、峰谷 | 是否含税及是否存在其他费用项待确认 |
| 优惠金额 | 应付金额与实付金额之间由优惠承担的金额 | `chargingDiscount` | `SUM(chargingDiscount)` | 字段非空；可信订单事实表 | 条件包含 | 是 | 是 | 全局、时间、站点、用户、支付方式 | 当前守恒关系为“实付 + 优惠 = 应付”；未支付订单优惠字段含义待确认 |
| 平均订单金额（应付） | 每笔可信订单平均产生的应付金额 | `chargingPay`, `orderNum` | `SUM(chargingPay) / COUNT(orderNum)` | `chargingPay` 非空；分母仅计金额非空订单 | 是 | 是 | 是 | 全局、时间、站点、枪口、用户 | 默认是应付客单价；如需平均实付金额必须单列，不能混用 |
| 每 kWh 收入（应付） | 每交付 1 kWh 对应的应付金额 | `chargingPay`, `chargingPower` | `SUM(chargingPay) / SUM(chargingPower)` | `chargingPower > 0` 且金额非空 | 是 | 是 | 否 | 全局、时间、站点、枪口、峰谷 | 不是利润或电价；实付版本应命名为“每 kWh 实付金额”；聚合后相除，不能直接平均订单比率 |
| 服务费占比 | 应付金额中服务费的结构占比 | `chargingServicePay`, `chargingPay` | `SUM(chargingServicePay) / SUM(chargingPay)` | 两字段非空且分母大于 0 | 是 | 是 | 条件包含 | 全局、时间、站点、枪口、峰谷 | 不代表毛利率；若零电量订单存在费用，其业务合理性应单独检查 |

## 5. 数据质量与异常

| 指标名称 | 业务含义 | 使用字段 | 计算公式 | 数据过滤条件 | 包含未支付订单 | 包含异常停止订单 | 包含零电量订单 | 粒度 | 注意事项 / 待业务确认点 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 未支付率 | 可信订单中明确处于未支付状态的比例 | `payStatus`, `orderNum` | `未支付订单数 / 支付状态已知订单数` | 分子 `payStatus = 未支付`；空值单独报告 | 指标对象 | 是 | 是 | 全局、时间、站点、枪口、用户、支付方式 | 其他支付状态如何归类、观察窗口结束时的支付滞后、退款订单处理均待确认 |
| 异常停止率 | 被业务字典认定为异常停止的订单占比 | `endReason`, `orderNum` | `异常停止订单数 / 可信订单量` | 需先建立并审批 `endReason` 分类映射 | 是 | 指标对象 | 是 | 全局、时间、站点、枪口、异常类别 | **待确认**：哪些停止原因属于正常、用户原因、车辆原因、设备原因、平台原因；未确认前不正式计算 |
| 零电量启动率 | 形成可信时长但未交付电量的启动尝试占比 | `chargingPower`, `orderNum`, `duration_minutes_calculated` | `chargingPower <= 0 的可信订单数 / 可信订单量` | 清洗后时长大于 0；电量缺失与电量为 0 应分别披露 | 是 | 是 | 指标对象 | 全局、时间、站点、枪口、启动方式、停止原因 | 当前指标反映启动/交付失败信号，不等同于设备故障率 |
| 设备类异常占比 | 异常停止中可归因于充电设备侧的比例 | `endReason`, `orderNum` | `设备类异常订单数 / 异常停止订单数` | 依赖经审批的停止原因归因字典 | 是 | 指标对象 | 是 | 全局、时间、站点、枪口、设备异常类别 | **待确认**：设备类边界及分母是否改为全部订单；不得仅按关键词自动归因后对外发布 |
| 费用不守恒率 | 应付金额与电费、服务费组成不一致的比例 | `chargingPay`, `chargingelectricityPay`, `chargingServicePay`, `fee_balance_ok` | `ABS(应付-电费-服务费)>0.01 的订单数 / 可校验订单数` | 三个金额字段均非空 | 是 | 是 | 是 | 全局、时间、站点 | 当前容差 0.01；币种最小单位或舍入规则变化时需调整 |
| 实付守恒异常率 | 实付加优惠与应付不一致的比例 | `chargingPayActual`, `chargingDiscount`, `chargingPay`, `payStatus` | `ABS(实付+优惠-应付)>0.01 的订单数 / 可校验订单数` | 三个金额字段均非空；支付状态分层展示 | 条件包含 | 是 | 是 | 全局、时间、站点、支付状态 | 退款、部分支付、预授权等业务流程是否存在，待确认后再决定异常规则 |
| SOC 数据异常率 | SOC 缺失、越界或结束 SOC 小于开始 SOC 的订单占比 | `beginSOC`, `endSOC`, `is_soc_missing`, `is_soc_reverse` | `SOC 异常订单数 / 可信订单量` | 分类型输出缺失、越界、倒挂，不合并掩盖原因 | 是 | 是 | 是 | 全局、时间、站点、枪口、车型（仅有合规维度时） | SOC 0 是否有效、不同协议上报机制及容差待业务/设备方确认 |

## 6. 暂不定义的指标

在缺少真实配置、在线状态、故障时长、排队、成本及退款数据时，暂不定义设备利用率、可用率、故障率、周转率、毛利率、净收入、配置枪均产出或站点健康分等内部 KPI。上述指标若进入后续阶段，必须先补充数据来源和业务审批口径。
